# Workflow

Every change goes through git.

- `main` is always in a working state.
- Work on a short-lived branch: `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, `chore/<topic>`.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat: add redocking sweep`, `fix: handle missing ligand`.
- Merge into `main` via pull request on GitHub (squash or merge commit), then delete the branch.
- Run `pytest tests/` before committing.

## What is versioned

Code, small curated tables (`data/*.csv`, `results/*.csv`) and figures are versioned.
Raw downloads (PDB files), docking poses, DiffDock outputs and logs are **not**: they are regenerated by the scripts in `scripts/`.
